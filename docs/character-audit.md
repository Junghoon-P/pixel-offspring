## 조사 범위와 재현

- 질문 6개 A/B 답변 64패턴을 실제 엔진으로 계산했다. 부모 외형은 10종이다.
- 고정 ID를 사용한 4096개 순서 있는 부모쌍에서 자식 외형 62종을 얻었다. UUID가 바뀌면 몸통 선택이 달라지므로 이 수를 전체 가능한 자식 수로 해석하지 않는다.
- 몸통6 × 표정2 × 허용 장식(1~2개)을 모두 열거하면 **84종**이다. 불꽃+새싹은 동일 슬롯이라 제외, 이불은 달팽이·유령·젤리만 허용했다.
- 84종을 공통 Canvas 렌더러로 표시해 전체 시각 검수했다. 64패턴/고정12쌍만 보던 갤러리의 사각지대를 보완했다.
- 빈 장식 레시피 12종은 스키마상 허용하지만 현 엔진의 정상 생성 결과는 아니므로 이번84종에서 제외했다. 비호환 이불, 중복 장식, 불꽃+새싹의 외부 입력 방어는 별도 항목이다.
- 재현: `node node_modules/.pnpm/vite-node@3.2.4_@types+node@22.20.5/node_modules/vite-node/vite-node.mjs --config vitest.config.ts scripts/audit-creatures.ts`.
- 산출물: `character-audit-data.json`. Next 페이지 `/docs/character-audit.html`이 이 데이터를 렌더링한다. JSON 재생성 후 프로덕션 확인에는 재빌드가 필요하다.

## 근본 원인과 수정 순서

1. **장식을 의미 있는 착용 구조가 아닌 범용 스티커로 취급했다.** 좌표 조절로 천·뿔·더듬이의 입체 관계를 해결하려 했다.
2. **호환 규칙이 너무 거칠다.** 현재는 이불의3몸통 허용과 불꽃/새싹 동시 금지만 있다. 보호 부위·착용 대상·얼굴 방향·앞뒤 레이어가 없다.
3. **논리적 조합 수를 시각 다양성/품질과 혼동했다.** 4096쌍 통과는 의미 있는84종 아트의 합격 근거가 아니다.

수정 작업 순서:
- [ ] 원본의 ‘불꽃 달팽이 + 이불 유령 → 이불을 덮은 달팽이’ 한 쌍을 먼저 완성한다. 달팽이 이불 고리 형태를 폐기하고 전용 드레이프를 제작한다.
- [ ] 같은 기준으로 유령·젤리 이불을 각각 제작한다. 머리 장식이 함께 있을 때도 앞뒤 관계를 정의한다.
- [ ] 반짝임·더듬이·뿔·부리 보호 영역과 표정 방향을 정리한다.
- [ ] 파츠별 안전 영역과 조합별 레이어를 데이터로 관리하고 공통 검증을 적용한다.
- [ ] 전체84종을 1/2/3배에서 재검수하고 부모→자식 비교, 저장 결과, 공유PNG를 확인한다.
- [ ] 그 뒤 새로운 설문 유형에 필요한 추가 파츠를 확장한다. 미완성84종을 더 늘리는 순서를 피한다.

## 합격 기준

- 이불 이름을 숨겨도 ‘몸을 덮은 천’으로 보인다. 테두리·액자·장신구처럼 보이지 않는다.
- 눈·더듬이·뿔 등 필요한 특징과 천의 앞뒤 관계가 자연스럽다. 모든 부위를 무조건 노출하는 것은 목표가 아니다.
- 반짝임/불꽃/새싹의 의미가 작은 크기에서도 식별되고 얼굴/더듬이와 우연히 합쳐지지 않는다.
- 두 부모의 전달된 특징과 생략된 특징을 결과 설명에서 확인할 수 있다.
- 픽셀/레이어 자동검사와 사람의 시각 검수를 모두 통과한다. 자동 통과만으로 ‘아트 완료’ 처리하지 않는다.

## 설문으로 이어지는 구조적 문제

- 몸통 비중(전체 답변을 동일 확률로 가정): 유령12/64, 버섯24/64, 달팽이12/64, 젤리4/64, 새8/64, 용4/64. 실제 사용자 분포를 측정한 값은 아니다.
- energy>0만 happy이고0도sleepy여서 sleepy48/64(75%)다.
- adventure>0이면 항상불꽃이므로 이16패턴은 계획/즉흥 답변이 외형에 영향을 주지 않는다.
- 성향3축 각각2문항으로 중간 점수가 많이 나오고, 27점수 조합이10외형으로 압축된다.
- 성격 설명·특수 능력은 에너지 평균에 따른2가지다. 질문을 추가해도 매핑을 바꾸지 않으면 다양성은 늘지 않는다.
- 다음 설문 작업은 `survey-v2-plan.md`의12문항·4축·16유형 초안에서 이어간다.
