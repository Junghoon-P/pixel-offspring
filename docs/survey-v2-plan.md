# 설문 v2 후속 초안

사용자 선택: **질문 수와 성향 유형을 더 다양하게.**
상태: 로컬 구현 및 회귀 검증 완료. 현재 화면은12문항 v2이며 v1 API·기존 스냅샷도 지원한다. 아래는 채택한 설계와 후속 사용성 검토 기준이다.

## 추천 범위

12문항·4성향 축·16기본 유형으로 확장한다. 축마다3문항을 두고 강제 양자택일의 합을 사용하면 동점 처리에 따른 졸린 표정 쏠림을 없앨 수 있다. 예상 소요시간은 실제 사용성 테스트 후 표시한다. 임의로 ‘1분’이라고 보장하지 않는다.

- 12문항/4축: 기존보다 선택 폭을 늘리면서 질문 길이를 관리하기 좋다. 첫 확장 추천안.
- 16~20문항/5축 이상: 더 다양한 세부 묘사가 가능하지만 질문 중복·이탈·아트/카피 범위가 함께 커진다. 첫 단계의 기본값으로 삼지 않는다.
- 유형은 놀이용 결과다. 실제 성격을 과학적으로 진단하는 명칭·점수 해석은 사용하지 않는다.

## 4축과 표현 연결

| 축 | 두 방향 | 결과에서 보여줄 차이 |
|---|---|---|
| 발견 | 익숙함 / 탐험 | 몸통 계열·탐험 관련 장식 후보 |
| 리듬 | 느긋함 / 활발함 | 표정·포즈·행동 설명 |
| 준비 | 계획 / 즉흥 | 소품·능력 문구. 다른 축 분기 때문에 무시하지 않는다. |
| 표현 | 담백함 / 풍부함 | 표정 강도·반응·친구와 함께 생기는 특성 |

성향 축과 생물 파츠를 무조건1:1로 매핑하지 않는다. 먼저16유형별 레시피를 확정하고 중복/시각 구분을 검사한다. 이름만16개이고 그림이 같은 문제를 피한다. 기존6몸통을 활용하되 승인된 표정·소품 변형을 조합한다. 신규 파츠 수는 캐릭터 감사 수정 뒤 확정한다.

## 12문항 초안

각 행의 점수 부호는 내부 값이다. 응답 화면에는 보이지 않는다. 축의 양 끝에 우열을 두지 않고 선택지 순서를 섞는다.

| 번호 / 축 | 질문 | A | B | A/B 점수 |
|---|---|---|---|---|
| 1 발견 | 산책 중 처음 보는 골목을 발견했다. | 늘 가던 길로 이어 걷는다 | 골목 안에 뭐가 있는지 들어가 본다 | -1 / +1 |
| 2 리듬 | 약속 없는 오후, 몸이 원하는 건? | 밖에서 이것저것 움직이기 | 한곳에서 느긋하게 쉬기 | +1 / -1 |
| 3 준비 | 친구와 작은 여행을 가기로 했다. | 꼭 갈 곳과 동선을 정해 둔다 | 도착해서 끌리는 곳을 고른다 | -1 / +1 |
| 4 표현 | 마음에 꼭 드는 선물을 받았다. | 왜 좋은지 신나게 이야기한다 | 오래 간직하며 조용히 고마워한다 | +1 / -1 |
| 5 발견 | 자주 가는 식당에 새 메뉴가 생겼다. | 오늘은 새 메뉴를 먹어 본다 | 좋아하는 메뉴를 다시 즐긴다 | +1 / -1 |
| 6 리듬 | 재미있는 하루를 보내고 집에 왔다. | 편한 자세로 쉬고 싶다 | 좋아하는 일을 조금 더 하고 싶다 | -1 / +1 |
| 7 준비 | 주말에 하고 싶은 일이 몇 가지 있다. | 그날 끌리는 것부터 한다 | 순서를 정해두면 마음이 편하다 | +1 / -1 |
| 8 표현 | 친구가 예상 밖의 웃긴 이야기를 했다. | 웃으면서 찬찬히 들어 준다 | 내 이야기도 보태며 반응한다 | -1 / +1 |
| 9 발견 | 취미에 쓸 작은 도구를 고른다면? | 써봐서 손에 익은 도구 | 아직 안 써본 새로운 도구 | -1 / +1 |
| 10 리듬 | 작은 축제에 놀러 왔다. | 여러 부스를 차례로 돌아보고 싶다 | 마음에 드는 곳을 오래 즐기고 싶다 | +1 / -1 |
| 11 준비 | 친구와 만날 날이 정해졌다. | 시간과 장소를 미리 정해두고 싶다 | 당일 상황을 보고 정하고 싶다 | -1 / +1 |
| 12 표현 | 마음에 드는 사진 한 장을 찍었다. | 바로 보여 주며 감상을 나눈다 | 혼자 몇 번 더 들여다본다 | +1 / -1 |

검토할 점: 4/12는 표현성과 공유 습관, 2/10은 활동성과 탐색 성향이 섞일 수 있다. 소규모 사용자 검수로 각 문항을 왜 선택했는지 확인하고 축 간 중복을 줄인다. 문항 수만 채우기 위해 비슷한 질문을 유지하지 않는다.

## 점수와 16유형

- 각 축의 합은 -3,-1,+1,+3. 부호4개로16유형을 정하고 절댓값은 설명 강도에만 사용한다.
- 이론상 답변 패턴은2^12=4096, 점수 프로필은4^4=256, 기본 유형은2^4=16이다. 실제 유저가 균등하게 분포한다는 뜻은 아니다.
- 균등 답변 전체 열거에서 각 유형256패턴인지 검사한다. 모든 답변을 A로 찍었을 때 한쪽 성향으로만 몰리는 문구도 점검한다.
- 유형 이름·능력·설명은16세트로 구성한다. 최종 이름은 외형과 함께 확정한다.

| 기본 묶음 | 계획·담백 | 계획·풍부 | 즉흥·담백 | 즉흥·풍부 |
|---|---|---|---|---|
| 익숙함·느긋함 | 포근한 기록가 | 다정한 준비꾼 | 느긋한 감상가 | 말랑한 이야기꾼 |
| 익숙함·활발함 | 동네 길잡이 | 든든한 분위기꾼 | 가벼운 산책가 | 흥겨운 단골 친구 |
| 탐험·느긋함 | 조용한 탐사자 | 호기심 수집가 | 느린 발견가 | 상상 여행가 |
| 탐험·활발함 | 씩씩한 개척자 | 신나는 원정대장 | 자유로운 모험가 | 반짝이는 즉흥가 |

위 이름은 작업용이며 타입별 우열·희귀도·유료 차등을 의미하지 않는다. 특정 응답이 언제나 ‘더 좋은 결과’로 보이지 않도록 문구와 아트를 함께 확인한다.

## 구현 순서와 완료 조건

1. 캐릭터 감사의 P0와 이불3종/얼굴 안전 영역을 먼저 해결한다. 확장 설문이 미완성 조합을 더 많이 만들지 않게 한다.
2. 12문항·4축·16유형 레시피/카피 표를 데이터로 작성한다. 축별 답변 변화가 결과에서 어디에 반영되는지 명시한다.
3. 기존 `catalog.ts`/`engine.ts`와 검증 스키마에 quizVersion2를 추가한다. 문항 수·질문 ID를6개 하드코딩한 부분을 버전별 정의에서 읽게 한다.
4. 초안 저장에 quizVersion을 넣고6문항 초안의12문항 오복원을 막는다. 이전 초안은 안내 후 새 설문으로 전환하며 몰래 답변을 보충하지 않는다.
5. 새 부모 스냅샷에 quizVersion·scoreVersion을 저장한다. 과거 원본 답변이 없으므로 이전 부모의 네 번째 축을 임의 재계산하지 않는다. 혼합 세대는 새 축 유전에서 제외하거나 명시적 호환 규칙을 적용한다.
6. 자식 엔진·카피 버전도 분리하고 기존 공동 결과는 그대로 읽는다. 링크/초대/소유권/삭제/멱등 저장은 유지한다.
7. 전체4096답변의 도달성/균형/결정성,16유형의 외형 중복, 대표 점수 프로필별 부모쌍과 역순 조합을 검사한다. 실제 카드/작은 화면/공유PNG를 검수한다.

수락 기준:16유형 모두 도달 가능, 현재처럼 특정 축이 다른 분기에 가려 무시되지 않음, 각 유형의 외형 또는 설명 차이가 명확함, 모든 질문의 이전/복구/누락 검증, 구버전 결과 불변, 아트 시각 승인.

## 구현 결과

- `survey.ts`의12문항·4축·16유형 적용.4096답변의 유형별256패턴·외형16종과 답변 순서 독립성을 확인했다.
- 발견/리듬/준비 축은 몸통6종과 소품에, 표현 축은 표정에 반영했다. 설명과 능력에는4축을 모두 사용한다. 예전의‘중립이면 무조건졸림’ 분기를 새 설문에서 제거했다.
- `quizVersion=2`, `scoreVersion=2`, `profile`을 부모 스냅샷에 저장한다. 이전 원본 답변을 복원하지 않는다.
- 혼합 세대의 자식은 누락된 표현 성향을 추정하지 않고 공통 문구와 안내를 사용한다. 양쪽이 v2이면4축 조합 카피를 사용한다. 평균이0이면 안정적으로 선택된 몸통 부모의 해당 축을 따른다.
- 새 조합은 engineVersion/copyVersion2. 몸통 선택의 기존 hash seed 규칙은 유지해 불필요한 외형 변동을 막는다. 기존 공동 결과는 저장된 snapshot 그대로 조회한다.
- 자신의 유형은 내 생물과 초대 화면에서 확인한다. 공유PNG는 긴 설명을 담도록 새 카피 버전에서 높이1600px를 사용한다.
- 이전6문항 초안은 닉네임만 유지하고 전환 안내 후 첫 질문부터 시작한다. 실패 재시도·12문항 초안 복구·친구 초대·실제D1 저장 검증 통과.
- 남은 제품 검증: 사용자 응답분포/질문 이해도/이탈률 및 문항 간 의미 중복. 이론적 균형을 실제 사용자 분포나 과학적 성격 타당성으로 주장하지 않는다.
