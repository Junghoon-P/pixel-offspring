# 도트 생물 조합 서비스 — 개발 작업 명세

작성일: 2026-10-20 · 상태: 구현 전 · 대상: 실제 개발 담당자

이 파일은 기획·디자인 준비와 구분해 실제 코드 작성·검증·운영 설정이 필요한 작업을 정리한다. 현재 구현된 앱이 있다는 의미는 아니다.

## 함께 읽을 자료

- [상세 개발 계획](2026-10-16-pixel-offspring.md): 질문, 점수표, 화면, 데이터·API, 보관·삭제와 전체 정책의 기준.
- [개발 시작 작업 프롬프트](2026-10-20-pixel-offspring-start-prompt.md): 개발 에이전트에게 전달할 실행 지시.
- [승인된 캐릭터 콘셉트](assets/pixel-family-concept.png): 불꽃 달팽이 + 이불 유령 → 불꽃 이불 달팽이.

기존 상세 계획의 추천 기본값은 이 개발안의 출발점이다. 사용자 확정 사항과 개발자의 제안을 구분해 기록한다. 숫자·화면·의존성이 바뀌면 구현과 문서를 함께 갱신한다.

## 1. 최종 개발 목표

회원가입 없이 질문에 답해 내 도트 생물을 만들고, 친구에게 초대한 뒤 두 캐릭터를 조합한 자식 생물을 이미지와 링크로 공유한다.

- 같은 캐릭터 쌍의 결과는 참여 순서·새로고침·동시 요청에 관계없이 동일하다.
- 하나의 초대 링크로 여러 친구와 각각 다른 결과를 만든다.
- 초대한 사람과 참여한 사람 모두 자신의 결과 목록에서 확인한다.
- 캐릭터는 실제 파츠를 합성한다. 사용자 요청마다 AI 이미지를 생성하지 않는다.
- 질문·문구는 오락용으로 제공하고 성격·관계를 진단하는 결과처럼 표현하지 않는다.

## 2. 착수 환경과 범위

- 실제 앱 개발 폴더에서 작업한다. 이 문서를 보관한 ‘커리어’ 프로젝트의 sources/ 및 이력서 파일은 개발 대상이 아니다.
- 기존 앱 저장소가 있으면 AGENTS.md, 의존성, 구조, 컴포넌트·훅·테스트·배포 설정부터 확인한다.
- 새 저장소는 React + TypeScript + Vite + Cloudflare Workers + D1을 기준으로 제안한다. 입력 검증은 Zod, 테스트는 Vitest·Playwright를 계획한다.
- 서버 상태 관리가 필요하면 TanStack Query를 검토하고 기존 프로젝트의 방식을 우선한다. 단순 질문 진행은 로컬 상태로 충분하다.
- 실제 설치 전에 기존 의존성과 적용 지시를 확인한다. 문서를 읽었다는 이유만으로 추가 의존성 사용이 승인된 것으로 해석하지 않는다.
- 로컬 완성과 외부 공개를 구분한다. 배포 계정이 없어도 로컬 DB·테스트·설정·실행 문서까지 완성할 수 있다.

## 3. 개발 항목과 완료 기준

### DEV-01. 프로젝트·개발 환경

**작업 대상:** package.json, 잠금 파일, TypeScript·Vite 설정, Workers 설정, 환경 변수 예시, README.

- [ ] 기존 구조를 확인하고 재사용 가능한 코드와 설정을 기록한다.
- [ ] 웹 화면과 API를 함께 로컬 실행하는 환경을 구성한다.
- [ ] 로컬·미리보기·운영 DB 바인딩과 환경 변수를 분리한다.
- [ ] 타입 검사·동작 테스트·빌드·브라우저 테스트 명령을 등록한다.
- [ ] 비밀값은 저장소에 넣지 않고 예시 파일에는 변수 이름과 설명만 적는다.

**완료:** 다른 개발자가 README대로 설치·실행·타입 검사·빌드할 수 있다. 클라우드 계정 연결이 없으면 그 부분만 미설정으로 표시한다.

### DEV-02. 성격·캐릭터·유전 엔진

**작업 대상:** src/domain/creature/model.ts, catalog.ts, generate.ts, generate.test.ts, src/shared/contracts.ts.

- [ ] 상세 계획의 6문항과 adventure·energy·spontaneity 점수표를 데이터로 정의한다.
- [ ] 답변의 누락·중복·알 수 없는 선택지와 버전을 검증한다.
- [ ] 64가지 답변 패턴이 유효한 부모 레시피로 변환되게 만든다.
- [ ] 부모 ID를 정렬하고 버전이 포함된 고정 시드로 자식의 파츠와 문구를 결정한다.
- [ ] 몸통·얼굴·장식의 실제 부모 출처를 기록하고 허용된 조합만 고른다.
- [ ] 기존 결과 스냅샷은 새 엔진 버전으로 재생성하지 않는다.
- [ ] 이름·설명·특수 능력은 준비한 문구 데이터에서 결정한다.

**먼저 검증:** 같은 입력, 부모 순서 반전, 동일 외형 부모, 자기 캐릭터 조합, 호환되지 않는 장식, 잘못된 답변, 버전 변경.

**완료:** 고정 예시 12쌍의 이름·그림·유전 내역이 일치하고 핵심 테스트가 통과한다. DB와 React 없이도 엔진을 테스트할 수 있다.

### DEV-03. 도트 파츠 렌더러

**작업 대상:** public/creatures/v1/, src/components/CreatureCanvas.tsx, 에셋 검사·미리보기.

- [ ] 콘셉트를 기준으로 투명 PNG 파츠와 몸통별 부착 좌표를 준비한다.
- [ ] 제안 규격 64×64px와 뒤 장식 → 몸통 → 얼굴 → 앞 장식 순서를 구현한다.
- [ ] 정수 배율·nearest-neighbor로 선명하게 확대한다.
- [ ] 누락된 파츠·좌표·파일을 검사하고 잘못된 레시피를 조용히 숨기지 않는다.
- [ ] 몸통별 허용 장식을 미리보기로 확인한다.
- [ ] 화면과 이미지 내보내기가 같은 렌더링 함수를 사용하게 한다.

**완료:** 불꽃 달팽이·이불 유령·자식의 실제 조합을 확인하고, 지원하는 조합에서 표정·장식이 잘리거나 부자연스럽게 겹치지 않는다.

**에셋 의존성:** 콘셉트 이미지는 편집 가능한 파츠가 아니다. 파츠가 없으면 엔진·서버 개발은 진행할 수 있지만 최종 캐릭터 렌더링의 시각 검증은 완료 처리하지 않는다.

### DEV-04. 모바일 사용자 화면

**작업 대상:** src/features/quiz/, invite/, result/, 공통 레이아웃·API 연결.

- [ ] 시작·질문·내 생물·초대·탄생 상태·결과 화면을 구현한다.
- [ ] 질문 앞뒤 이동, 진행률, 초안 복구, 제출 중 중복 클릭 방지를 구현한다.
- [ ] 친구 초대 링크를 유지한 채 내 캐릭터를 만들고 참여 화면으로 돌아온다.
- [ ] 내 결과 목록은 최신순·20개 단위 커서 페이지로 제공한다.
- [ ] 빈 목록·네트워크 오류·저장 실패·만료 링크·세션 유실을 구분해 안내한다.
- [ ] 모바일 너비 360px·390px, 키보드·스크린리더·터치 영역을 확인한다.
- [ ] 탄생 연출은 저장 성공 후 시작하고 건너뛰기·reduced-motion을 지원한다.

**완료:** 사용자가 질문에 답해 자신의 캐릭터를 확인하고, 실패 시 내용을 잃지 않고 재시도할 수 있다. API 연결 전 화면은 로컬 미리보기임을 구분한다.

### DEV-05. API·DB·익명 관리 권한

**작업 대상:** worker/routes/, repositories/, security/, migrations/, scheduled/cleanup.ts.

- [ ] 상세 계획의 sessions·characters·invites·results·request_keys·daily_metrics를 구현한다.
- [ ] 세션, 캐릭터 생성·조회·삭제, 초대 생성·조회, 조합, 결과 조회·목록 API를 구현한다.
- [ ] HttpOnly·Secure·SameSite 쿠키와 소유권·Origin 검증을 적용한다.
- [ ] 원본 답변을 영구 저장하지 않고 검증된 점수와 레시피만 저장한다.
- [ ] 부모 쌍 고유 제약과 생성 요청 키로 동시 요청·재시도 중복을 막는다.
- [ ] 같은 초대의 여러 참여자를 보존하고, 부모 양쪽의 소유자가 결과를 조회하게 한다.
- [ ] 보관·삭제·만료와 관련 공동 결과 비공개·정리 작업을 구현한다.
- [ ] 본문 크기, 닉네임, ID, 커서, 요청 빈도와 오류 응답을 검증한다.

**먼저 검증:** A→B·A→C·B→A·A→A, 20개 동시 요청, 응답 유실 후 재요청, 타인 ID 사용, 삭제와 생성의 경합, 만료 링크, 페이지 중복·누락.

**완료:** 별도 브라우저 두 개에서 실제 저장·초대·탄생·양쪽 재조회·삭제가 동작한다. 공개 링크에 관리 토큰·원본 답변·타인의 비공개 목록이 노출되지 않는다.

### DEV-06. 결과 카드와 공유

**작업 대상:** src/features/result/, worker/routes/share.ts, 공통 카드 렌더러.

- [ ] 부모 2개·자식·닉네임·유전 내역·능력을 담은 PNG 카드를 만든다.
- [ ] 폰트·이미지가 준비된 후 내보내고 한글·긴 문구의 줄바꿈을 검증한다.
- [ ] PNG 준비 후 사용자 클릭에서 파일 공유를 호출한다.
- [ ] 파일 공유가 없으면 링크 공유·복사·저장 대안을 제공한다.
- [ ] 공유 취소는 오류 알림으로 취급하지 않는다.
- [ ] /r/:resultId 초기 HTML에 제목·설명·공통 OG 이미지를 제공한다.

**완료:** 저장한 카드와 화면이 같은 결과이며, 공유 링크를 다른 브라우저에서 열어 같은 결과를 확인한다. 공통 OG와 개인화 미리보기를 혼동하지 않는다.

### DEV-07. 자동 검증·측정·운영 설정

**작업 대상:** tests/e2e/, 이벤트 집계, 요청 제한, Workers·배포 설정, README.

- [ ] 질문·엔진·권한·DB 핵심 동작의 실패 테스트를 먼저 작성하고 통과시킨다.
- [ ] 두 브라우저 초대·참여·원 사용자 결과 확인·공유·삭제 E2E를 만든다.
- [ ] iOS Safari·Android Chrome·카카오톡 인앱 브라우저의 실제 검증 결과를 남긴다.
- [ ] 사용 가능한 API 요청 제한과 신규 생성 중지 설정을 구현한다.
- [ ] 개인정보 없는 일자별 이벤트 집계를 연결한다. 공유 시도와 실제 게시·저장 완료를 구분한다.
- [ ] 허용된 환경에서 요청·CPU·DB 읽기/쓰기·저장 증가를 측정해 비용 가정을 갱신한다.
- [ ] 미리보기·운영 분리, 마이그레이션·복구·롤백·데이터 정리 절차를 문서화한다.

**완료:** 타입 검사·테스트·빌드·E2E가 통과하고, 실제 확인한 환경·미검증 환경·외부 설정이 필요한 항목이 구분돼 있다. 배포했다면 운영 URL에서 전체 흐름을 다시 검증한다.

## 4. 실제 개발 순서

| 마일스톤 | 포함 개발 | 확인할 결과 |
| --- | --- | --- |
| M1. 조합 데모 | DEV-01 + DEV-02 + DEV-03 최소 파츠 | 두 부모를 고르면 자식과 유전 설명이 보임 |
| M2. 혼자 참여 | DEV-04 질문·내 생물 | 질문 6개로 내 캐릭터가 생성됨 |
| M3. 친구 연결 | DEV-05 + DEV-04 API 연결 | 두 브라우저에서 초대·참여·양쪽 결과 조회 |
| M4. 공유 | DEV-06 | 카드 저장·링크 공유·같은 결과 재조회 |
| M5. 출시 준비 | DEV-07 + 전체 예외 처리 | 자동·실기기 검증, 운영 설정·비용 확인 |

M1은 첫 검증 지점이지 최종 개발 범위가 아니다. 전체 첫 출시 개발을 지시받았다면 M1 결과를 공유하고 M2~M5를 계속 진행한다. 외부 계정·에셋·권한이 필요한 항목은 그 항목만 구분해 알린다.

## 5. 개발과 구분해 준비할 것

| 준비 항목 | 개발과의 연결 |
| --- | --- |
| 질문·이름·능력 문구 | 상세 계획의 초안으로 엔진 개발 가능, 공개 전 문구 검토 |
| 실제 도트 파츠 | 최소 부모 2종부터 제작, 최종 렌더링·공유 시각 검증에 필요 |
| 화면 디자인 | 승인 시안의 정확한 색을 확인하고, 미확정 화면 디자인은 별도 검토 |
| 실제 개발 폴더 | 착수 장소가 있어야 환경 구축 가능 |
| Cloudflare·도메인 | 로컬 구현 이후 실제 미리보기·운영 배포에 필요 |
| 실기기 접근 | 브라우저 자동화와 별개로 실제 공유 동작 확인에 필요 |

## 6. 개발 완료 보고 형식

1. 실행 방법과 확인 가능한 로컬 주소 또는 미리보기 URL.
2. 마일스톤별 구현·검증 완료 여부.
3. 사용한 실제 캐릭터 에셋·출처·남은 제작 항목.
4. 실행한 검사 명령과 결과, 브라우저 검증 증거.
5. 측정한 사용량과 비용 추정의 전제.
6. 미검증·미설정·사용자 결정이 필요한 항목과 영향.

핵심 개발 순서는 **조합 엔진·렌더러 → 참여 화면 → 초대·저장 → 공유 → 검증·출시 준비**다.
